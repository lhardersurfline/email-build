Claude vEmailBuild

How a request turns into a finished email file

Four inputs feed one build loop, which always lands in the same four folders. Nothing gets overwritten — every save is a new version.

Inputs
Skill

email-html-mjml

Turns MJML into client-safe HTML. This is what actually compiles the email.

Setup

Install the modified email-html-mjml skill in Claude Desktop.

MCPs

Filesystem MCP
Figma MCP

Filesystem reads/writes files on Leif's machine. Figma pulls specs and assets from whatever file is open in the desktop app.

Setup

Connect both MCP servers in Claude Desktop. Figma MCP only sees a file once it's open in the Figma desktop app.

Instructions

_Instructions.md

The rulebook: never overwrite, always version, always preview before saving, always ask where to place the result.

Setup

Keep this file at the project root — it's re-read at the start of every session.

↓ ↓ ↓ ↓
Build loop
01

Read context + instructions

Everything in /Context and _Instructions.md loads before any work starts.

02

Pull the design spec

If a Figma file is open, Figma MCP reads exact layout, spacing, and copy from it.

03

Build or edit the email

MJML is written or edited, then compiled to HTML via the email-html-mjml skill.

04

Preview in chat

Both the rendered HTML and the raw code are shown — one to check visually, one to copy into an external previewer.

05

Leif signs off

Once approved, Leif's told where it's going: /Context, /Drafts, or /Outputs.

06

Archive, then save

Any prior version moves to /Archive via Filesystem MCP first — never deleted, never overwritten.

↓ ↓ ↓
Where it lands

/Drafts

Work in progress — not yet approved.

/Outputs

The current, ready-to-use version of a template.

/Archive

Every superseded version, kept — never deleted.

Every filename carries its own history, so nothing needs a changelog.
